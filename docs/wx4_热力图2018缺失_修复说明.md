## 二、你点名的三处，逐条排查结果

### ① 后端 SQL 有没有写死 `WHERE CreateTime >= '2019-01-01'`

- 位置：`D:\PyWxDump_Source\pywxdump\db\dbMSG.py` → `get_date_count()`（第 190 行起）
- 原文逻辑：

  ```python
  sql_time = "AND CreateTime BETWEEN ? AND ? " if start_time and end_time else ""
  ```

- 也就是**只有 start_time 和 end_time 同时非 0 才加时间过滤**。而热力图页面前端传进来的就是 `[0, 0]`，所以是**全量查询，不存在 2019 下限**。
- 该 SQL 里唯一的过滤条件是 `StrTalker NOT LIKE '%chatroom%'`（排除群聊），与年份无关。

### ② 后端「最早/最晚年份」有没有算错

- 后端**不返回年份**，只返回 `{日期: {sender_count, receiver_count, total_count}}`（日期是 `YYYY-MM-DD` 字符串）。
- 年份由前端从日期键现取：
  `let m = parseInt(最小日期键.split("-")[0]), _ = parseInt(最大日期键.split("-")[0])`，再 `for (let S = m; S < _ + 1; S++)` 逐年生成日历列。
- 计算无错，且不写死年份。

### ③ 前端 ECharts 有没有硬编码 `['2019', '2020', ..., '2026']`

- 位置：`D:\PyWxDump_Source\pywxdump\ui\web\assets\StatisticsView-_MI6G2N3.js`
- 全文件搜索 `2018` / `2019` / `minDate` / `maxDate`：**无年份硬编码**。
  （唯一命中的 “2019” 是内置 xlsx 库的版权注释 `Copyright 2011 - 2019`，无关。）
- 顶部「年份：」下拉同样是**动态生成**：
  `Array.from(new Set(Object.keys(数据).map(b => b.split("-")[0]))).sort()`

### 补充：为什么是「画布放大 + 容器滚动 + 年份下拉」而不是 `dataZoom`

ECharts 的 `dataZoom` **不支持 calendar（日历）坐标系**，加了不生效。所以多年可查看靠这三件事（早前那轮已落盘并实测）：

1. 外层 `el-main` 允许滚动（`overflow: auto`）；
2. 画布宽度按年份数放大：`50 + 200 × 年份数 + 220` px，高度 1360px；
3. 顶部加「年份：」下拉（默认「全部年份」，可选某一年）。

本轮实测（柳岸 9 年）：画布 **2070 × 1360**（`50 + 200×9 + 220 = 2070` ✓），内层滚动容器 `scrollWidth 2110 > clientWidth` ✓ 横向滚动条有效。

## 三、真正的原因：数据源缺分片

微信 4.x 的消息库按时间轮转分片，柳岸的时间轴如下（每库一个时间段）：

| 分片 | 覆盖时间段 |
| --- | --- |
| message_0 | 2026-04-10 ~ 2026-10-04 |
| message_1 | 2025-04-10 ~ 2026-04-10 |
| message_2 | 2024-04-10 ~ 2025-04-10 |
| **message_3** | **2023-04-11 ~ 2024-04-10** |
| message_4 | 2022-04-11 ~ 2023-04-11 |
| message_5 | 2021-04-16 ~ 2022-04-11 |
| message_6 | 2020-04-11 ~ 2021-02-26 |
| message_7 | 2019-04-12 ~ 2020-04-10 |
| **message_8** | **2018-09-12 ~ 2019-04-12** |

缺的正是 `message_3` 和 `message_8` 这两块 —— 所以明细页和热力图都看不到 2018。

现在这两个分片在解密目录里，且会被自动纳入数据源：

```
C:\Users\Administrator\wxdump_work\decrypted_wx4\<本人wxid>_fed4\
    message_0_decrypted.db  ...  message_8_decrypted.db     （9 个消息分片）
    message_fts_decrypted.db / message_resource_decrypted.db （辅助库，不参与统计）
```

纳入规则（`pywxdump\db\dbbase.py`）：同目录下以 `message` 开头、且文件名**不含** `fts` / `resource` / `merge` / `wal` / `shm` / `journal` 的 `.db`，全部自动并入，无需手动配置。
